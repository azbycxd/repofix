# RepoFix 口述稿：只讲有证据的工程事实

## 30 秒：项目概述

我做的是一个 Coding Agent Harness 实验平台。输入 Git 仓库和问题描述，让模型调用工具
读代码、修改和验证，最后输出补丁。我重点处理的不是多加几个工具，而是三个可靠性问题：
测试有没有真的执行、反复无进展怎么收敛、进程崩溃后能不能恢复一致状态。
我用真实 Docker 故障注入验证机制，再让 DeepSeek 跑固定开发题、由官方 SWE-bench 独立判分。
本地验证、模型提交和官方 resolved 是三个独立结果，不能混成一个成功字段。

## 90 秒：架构

整体是一个单 Agent ReAct loop，模型负责决策，Runtime 负责工具执行。公开入口没有重写，
新增可靠性逻辑通过显式 profile 接进已有 loop，旧接口持续回归。

执行层在 Docker 里，工作目录是 testbed，运行期断网，有内存、CPU、PID 和 capability 限制。
普通 shell 提供原始命令反馈，结构化验证走独立 run_tests，直接传 argv，不让模型拼 shell
管道或自选报告路径。验证完成后，宿主保存 JUnit、输出和工作区哈希。

主循环旁边还有两块。ProgressMonitor 看实际文件版本和工具结果是否有变化，先提醒，
再有限重规划，最后 stuck；它不是另一个 Planner。Checkpoint 把消息、预算和工作区
绑定到同一 generation，执行工具前必须先落盘。恢复时对不确定的在途操作不重放。

最后产出的 patch 是候选结果。本地测试只证明这组测试通过，是否满足任务由独立 Judge
决定。日志里标清是模型建议、Harness 事实还是 Judge 结果，并保留原始文件哈希供复核。

## 90 秒：验证误判如何修

最典型的问题是 `pytest | tee`。如果只看 shell 最终退出码，tee 成功会掩盖 pytest 失败。
类似地，打印“测试成功”或者让验证模型说 PASS，都不是实际测试证据。

我做了两层区分。第一层是执行语义：普通 shell 开 pipefail，明确 timeout、running 和错误，
但这仍不能成为本地验证 PASS。第二层是专门的 run_tests：宿主控制 argv 和唯一 JUnit
报告路径，检查真实退出码、实际测试数量、失败/错误和工作区版本。无测试、全跳过、
环境错误、报告缺失都不能 PASS。通过之后再编辑，证据会 STALE。

我也做了正向用例，避免系统靠一律拒绝得到“零误放行”。一个 Docker 夹具里，本地选中的
测试确实通过，但另一个干净容器的隐藏测试仍失败。这证明本地 PASS 的范围有限，不能
把它叫作需求完成。官方 Django 镜像没有 pytest 的情况也原样记成环境限制，没有为跑分
放宽规则。

## 60 秒：崩溃恢复

恢复不能只存一个 JSON。我让每个 checkpoint generation 对应一份状态和一份有哈希的
工作区快照，写入使用原子替换和 fsync，加载要验证两者配对。工具执行前保存 assistant
和 pending calls；如果中途崩溃，新进程回填 INTERRUPTED_UNKNOWN，而不是自动再执行。

测试不是抛个异常模拟死亡：我启动独立 Python 进程连真实 Docker，在执行前、编辑后、
写入中和有后台任务时用 SIGKILL，确认退出 -9，再开新进程恢复。还损坏 manifest/blob，
测试回退旧完整代。步数、费用不能重置，旧后台任务标 LOST。

这里仍有边界：工作区快照是双签名的乐观一致性检查，不是对恶意并发写者的文件系统级
原子快照；我也没有测断电或跨机器恢复。

## 60 秒：实验和局限

机制数字要和模型数字分开。FakeModel 用于确定性协议；Docker 故障用真实容器、真实
进程和真实 pytest；真实模型任务由 DeepSeek 完成，再让官方 Judge 判分。
这轮全量离线 210 项通过，26 个不同 Docker 用例实际通过；负向误放行 0/21，同时正向
误拦截 0/3。固定三个 DEV 官方判分 3/3，估算模型费约 0.0191 美元。

但我不会只讲 3/3：三题都缺 pytest，本地结构化验证是 INCONCLUSIVE，Agent 最后
no_tool_call，并没有顺畅完成提交；是保存的候选 patch 通过了独立 Judge。
真实仓库 176 次 checkpoint 累计约 472 秒，也暴露了明显的持久化开销，不能说免费。

三个开发题以前参与过开发，只能叫固定 DEV 端到端回归，不能叫未见题泛化能力。
监测和 checkpoint 的开销按样本逐次记录、报告 median，没有用小样本吹 P99。
成本是响应 usage 乘固定配置价格，不等于供应商账单；重试或无 usage 时有不可知部分。

目前只支持可信 Python 仓库，Docker 默认 root、构建期依赖会执行代码，不是多租户安全
沙箱。我的工程结论是把“做了什么、知道什么、不知道什么”做成可以验证的合同，
而不是说已经解决了 Agent 的全部可靠性问题。

以上口述数字对应 2026-10-10 的 Evidence Report；精确费用为 $0.019057440，
63 次已返回模型调用、370783 tokens；含环境初始化与判分的 live 驱动耗时约 22.46 分钟。

## 不能说的话

- 不能把三道已知 DEV 的结果称为整个 SWE-bench 成功率。
- 不能把 FakeModel 的通过数当成真实模型能力。
- 不能说本地 PASS 证明需求覆盖充分，或四个 submit 之后就是修好。
- 不能说 checkpoint 对任意故障都保证 exactly-once；这里是未知调用不自动重放。
- 不能说 shell 前缀权限规则能安全执行任意恶意仓库。
- 不能用旧版本历史数字编造本轮收益，也不能声称 Context/子 Agent 的收益已经单独实测。
